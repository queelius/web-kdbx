# web-kdbx L1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build web-kdbx L1: browser-side KDBX UI with editable working copy backed by localStorage, plus download-as-export. Realizes the "vault is hosted at a URL, page bundles a canonical .kdbx, localStorage holds working edits" model.

**Spec:** `docs/superpowers/specs/2026-05-06-web-kdbx-l1-storage-design.md`

**Architecture:** Same single Rust crate as L0 (cdylib + rlib). New write methods on `Vault` exposed via wasm-bindgen, returning the re-encrypted KDBX bytes that JS can persist. New JS storage adapter (`www/storage.js`) wraps localStorage with vault-id keying. Auto-save on every write tool: Rust returns updated bytes, JS writes to localStorage. New UI components for edit mode (`vault-entry-edit`, `vault-add-entry`). Download/revert buttons in the existing `vault-app` shell.

**Tech Stack:** Same as L0. New Cargo feature: `save_kdbx4` (already supported by keepass 0.12; just needs to be enabled). No new dependencies.

**Mental model (from spec):**
- A vault is identified by `origin + bundled-vault-name` (Mode 1) or `"byo:" + name` (Mode 2)
- localStorage holds whole encrypted KDBX bytes per vault-id
- Auto-save: every write returns updated bytes, JS persists immediately
- Download: `Blob.from(localStorage[vault-id])`, served as `vault.kdbx`
- Revert (Mode 1 only): clear localStorage entry, reload from bundled

**Exclusions (from spec):**
- No File System Access API integration. Tier 2 (download) only.
- No remote backends (Dropbox, etc.).
- No multi-recipient sharing (Layer 2 territory).
- No concurrent multi-device sync.
- Diff visualizer (`kdbx_diff_pending` style) is **optional** for L1; this plan deletes it from scope. Future work: separate plan that pulls in `diff-kdbx` as a WASM dependency.

**API surface caveats:**
- `keepass = "0.12"` write methods need the `save_kdbx4` feature. The Cargo.toml only enables `serialization` today; we add `save_kdbx4` here.
- Recently-merged keepass-rs#321 added `EntryRef::attachments_named()`. The `src/attachments.rs` JSON-roundtrip workaround can be replaced as part of this work.
- `Database` write API in 0.12: see `Database::add_entry`, `EntryMut::edit`, `EntryMut::set` (and friends). UUIDs are generated automatically.
- Atomic-write semantics for localStorage: `setItem` is synchronous and atomic at the API level. Quota-exceeded throws `DOMException`; we surface that as a user-visible error.

**Audit invariants to preserve (from spec):**
- localStorage stores ONLY raw encrypted KDBX bytes (one key per vault).
- No IndexedDB, no OPFS, no Service Worker, no cookies, no `caches.open`.
- Master password never leaves WASM volatile memory.
- L1 makes zero network requests after initial page load (no fetch beyond the bundled-vault URL on first load).

```rust
#[wasm_bindgen]
impl Vault {
    /// Update a single field on an existing entry. Returns the new
    /// encrypted KDBX bytes for the JS layer to persist to localStorage.
    pub fn update_field(
        &mut self,
        entry_uuid: &str,
        field_name: &str,
        value: &str,
        protected: bool,
    ) -> Result<Vec<u8>, JsError> {
        let target = uuid::Uuid::parse_str(entry_uuid).map_err(|_| JsError::new("Invalid UUID"))?;
        let entry_id = self.find_entry_id(target).ok_or_else(|| JsError::new("Entry not found"))?;

        let mut entry_mut = self.db.entry_mut(entry_id).ok_or_else(|| JsError::new("Entry not found"))?;
        entry_mut.edit(|e| {
            let v = if protected {
                keepass::db::Value::protected(value)
            } else {
                keepass::db::Value::unprotected(value.to_string())
            };
            e.set(field_name, v);
        });

        self.save_to_bytes()
    }

    /// Add a new entry to the specified group. Returns the new
    /// encrypted KDBX bytes for the JS layer to persist.
    pub fn add_entry(&mut self, input: JsValue) -> Result<Vec<u8>, JsError> {
        let input: EntryInput = serde_wasm_bindgen::from_value(input)
            .map_err(|e| JsError::new(&format!("Invalid input: {}", e)))?;
        // ... locate group, create entry, set title and fields, insert ...
        self.save_to_bytes()
    }

    /// Re-encrypt the in-memory database to KDBX bytes.
    /// JS persists these to localStorage[vault-id] as the working copy.
    pub fn save_to_bytes(&self) -> Result<Vec<u8>, JsError> {
        let mut buf = Vec::new();
        self.db.save(&mut buf, self.key.clone())
            .map_err(|e| JsError::new(&format!("Save failed: {}", e)))?;
        Ok(buf)
    }
}
```

Note: `Vault` needs to retain the `DatabaseKey` so `save_to_bytes` can re-encrypt. Currently `Vault` only stores `db: keepass::Database`; we add `key: keepass::DatabaseKey`.

## Task 4: JS storage adapter

**Files:**
- Create: `www/storage.js`

A small module wrapping localStorage with vault-id keying and explicit error handling. This is the **only** place that writes to localStorage; the audit gate enforces it.

- [ ] **Step 1:** Implement vault-id derivation:

```js
// www/storage.js
const KEY_PREFIX = 'web-kdbx:vault:';

export function vaultIdFromAttrs({ vaultUrl, vaultId }) {
    if (vaultId) return vaultId;
    if (vaultUrl) {
        // Mode 1: hosted vault. Use origin + path.
        return `${location.origin}${vaultUrl.startsWith('/') ? vaultUrl : '/' + vaultUrl}`;
    }
    // Mode 2: BYO. Caller must provide an identifier (e.g., file hash).
    return null;
}

export function loadWorkingCopy(vaultId) {
    const raw = localStorage.getItem(KEY_PREFIX + vaultId);
    if (!raw) return null;
    return base64ToBytes(raw);
}

export function saveWorkingCopy(vaultId, bytes) {
    try {
        localStorage.setItem(KEY_PREFIX + vaultId, bytesToBase64(bytes));
    } catch (e) {
        if (e.name === 'QuotaExceededError') {
            throw new Error('Browser storage quota exceeded. Download your vault and clear old vaults.');
        }
        throw e;
    }
}

export function clearWorkingCopy(vaultId) {
    localStorage.removeItem(KEY_PREFIX + vaultId);
}

export function hasWorkingCopy(vaultId) {
    return localStorage.getItem(KEY_PREFIX + vaultId) !== null;
}

function bytesToBase64(bytes) {
    let binary = '';
    for (let i = 0; i < bytes.length; i++) binary += String.fromCharCode(bytes[i]);
    return btoa(binary);
}

function base64ToBytes(b64) {
    const binary = atob(b64);
    const bytes = new Uint8Array(binary.length);
    for (let i = 0; i < binary.length; i++) bytes[i] = binary.charCodeAt(i);
    return bytes;
}
```

- [ ] **Step 2:** Confirm the bytes encoding round-trips correctly (base64 of binary bytes is the only practical way to put binary in localStorage; localStorage values must be strings).

- [ ] **Step 3:** Define the load priority helper:

```js
export async function loadVaultBytes({ vaultUrl, vaultId }) {
    const id = vaultIdFromAttrs({ vaultUrl, vaultId });
    if (id) {
        const working = loadWorkingCopy(id);
        if (working) return { bytes: working, source: 'localStorage', vaultId: id };
    }
    if (vaultUrl) {
        // Fetch the bundled canonical vault.
        const resp = await fetch(vaultUrl);
        if (!resp.ok) throw new Error(`Failed to fetch ${vaultUrl}: ${resp.status}`);
        const bytes = new Uint8Array(await resp.arrayBuffer());
        return { bytes, source: 'bundled', vaultId: id };
    }
    return null; // BYO mode: caller will receive bytes from file picker
}
```

- [ ] **Step 4:** No tests at this level (storage.js is too thin for unit tests; covered by Layer 3 e2e).

```js
class VaultDownloadButton extends HTMLElement {
    connectedCallback() {
        const btn = el('button', { className: 'download-btn', onClick: () => this._onDownload() }, ['Download Vault']);
        this.appendChild(btn);
    }

    _onDownload() {
        // For Mode 1: prefer localStorage working copy; fall back to bundled.
        // For Mode 2: in-memory bytes from the Vault (re-encrypted on demand).
        const bytes = this._app.currentBytes(); // helper on vault-app
        const blob = new Blob([bytes], { type: 'application/x-keepass2' });
        const url = URL.createObjectURL(blob);
        const a = document.createElement('a');
        a.href = url;
        a.download = this._app.suggestedFilename(); // e.g. "vault.kdbx"
        document.body.appendChild(a);
        a.click();
        document.body.removeChild(a);
        URL.revokeObjectURL(url);
    }
}
```

**Files:**

- [ ] **Step 1:** Implement the storage audit script:

```bash
#!/usr/bin/env bash
# ci-audit-storage.sh: enforce L1 storage purity invariants.
# Runs grep checks; exits non-zero if any forbidden API usage found.

set -e

echo "Auditing localStorage usage scope..."

# All localStorage writes MUST be in www/storage.js.
LS_WRITES=$(grep -rn "localStorage\.setItem\|localStorage\[" www/ \
    --include='*.js' \
    --exclude='storage.js' || true)
if [ -n "$LS_WRITES" ]; then
    echo "ERROR: localStorage writes outside www/storage.js:"
    echo "$LS_WRITES"
    exit 1
fi

echo "Auditing forbidden storage APIs..."

# No IndexedDB, OPFS, Service Worker, caches, cookies in production code.
FORBIDDEN=$(grep -rEn "indexedDB|navigator\.storage\.getDirectory|serviceWorker\.register|caches\.open|document\.cookie" www/ \
    --include='*.js' \
    --exclude-dir='__tests__' || true)
if [ -n "$FORBIDDEN" ]; then
    echo "ERROR: forbidden storage API usage:"
    echo "$FORBIDDEN"
    exit 1
fi

echo "Storage audit passed."
```
